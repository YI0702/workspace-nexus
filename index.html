📜 PROJECT SOUL

联盟样式工作台 · 项目灵魂

任何团队成员或 AI 工具开始工作前，请先读一遍这一页。它是这个项目"统一的上下文起点"。

① 我们在做什么

一句话定义：用 AI 重构联盟样式工作的基础设施，把分散的样式生产、规则配置、洞察归因、问题排查整合成一个 AI 原生的一站式工作台。

项目的一体两面：

  • 面一：探索 AI 原生的协作方式和工作方法——借这个项目走通"Demo + 一页纸 + 决策档案"的新交付契约
  • 面二：零基思维 · 用 AI 重构样式工作基础设施——从零思考"如果今天才开始做，应该长什么样"

MVP 锚点：6/30 跑通端到端流程，以"开屏"场景为例（线上真实用例，不是 mock）。

② 我们已经达成的共识（不再讨论）

5/19 商业产品同学脑暴会，已对齐四类共识——这些不再重复讨论，是后续所有工作的背景：

  1. 痛点：业务理解黑盒 / 规则配置耗精力 / 流程流转慢 / 效果归因难 / 技术支持沉淀缺失 / Case 排查难
  2. 理想态：流程打通 · 创作低门槛 · 业务×技术理解打通 · 项目制协同。AI 辅助提效，最终决策靠人。
  3. 路线图：① 交互模式 = Agent + 强定义工作流 + 全局看板 + Skills 共创；② 封闭定义 + 开放共创结合；③ 先主流程上线、再历史迁移；场景内小闭环优先。
  4. AI Native 阶段性认知：上下文充分共享 / 广泛引入 AI 能力 / 业务优先，AI 是手段不是目的

→ 详见决策档案

③ 我们的工作原则（行事坐标）

P1
每人独立 own 一个模块 · PM 提供基座骨架
模块定义权属于 owner 自己；PM 提供需要拉通的基座，重要定义内部讨论后形成共识。基座是底稿不是终稿。
P2
交付契约：统一交付物 + 开放生产工具 + AI in ALL
交付物 = 可交互 Demo + 一页纸业务逻辑（含 Review 关键问题回答）；生产工具自由选；每个环节都用 AI 提效。
P3
Demo First · 不写 TAPD/PRD
视觉部分 Demo 覆盖（更准确），逻辑部分一页纸覆盖（回应 Review 清单），过程沉淀决策档案。
P4
封闭定义 + 开放共创
主流程的强定义部分（流量规范 + 平台 & 数据范围）封闭定义保稳定；子流程通过 Skills 形式有限开放，经审计上架。

📋 路演反馈模板

适用：产品内部路演（如 5/29 流量产品内部路演）。视角：业务、产品定义、用户体验。

① 评审场次：XXX 模块 · YYYY-MM-DD · 主讲人 · 参与方
② 关键反馈（3-5 条，按重要性排序）：每条标注「针对什么 + 谁提出 + 是否需要响应」
③ 待回应问题：owner 需在 N 天内闭环的问题清单
④ 决策动作：如有产生项目级决策，链接到决策档案

💡 路演结束后用 AI 工具读会议录音/纪要，按上面 4 个字段输出初稿，owner 校准后入档。

📋 研发 KO 反馈模板

适用：研发 KO 及后续研发对接会议。视角：技术可行性、排期、风险、依赖。

① 对接场次：XXX 模块 · YYYY-MM-DD · 研发对接人 · 产品 owner
② 技术评估：可行性 / 实现路径 / 关键技术挑战 / 替代方案
③ 排期与依赖：预估工时 + 阻塞项 + 跨模块/跨团队依赖
④ 待澄清问题：产品和研发各自需要补充的细节
⑤ 决策动作：如产生项目级决策，链接到决策档案

💡 KO 后建议 24 小时内由产品和研发各填一份反馈视角，对照看差异——这是发现"产品理解 ≠ 研发理解"的最好时机。
